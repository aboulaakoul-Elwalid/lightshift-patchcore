Reading it. Vanilla uses the threshold fixed on the original lighting. B3 keeps the model but sets the threshold to the ⌈(n+1)(1−α)⌉-th smallest of the k calibration scores: at most ≈10% of good parts should then raise a false alarm. B2+B3 first subtracts the per-channel feature offset (new lighting vs original), then recomputes the threshold on the aligned scores. A good part wrongly flagged is a false alarm; a defect that scores below the threshold is a miss. Raising the threshold (e.g. the maximum) trades false alarms for misses. Full explanation and numbers: the learning report. Backend: FastAPI, CPU inference.
